### 2.2 Identity rules

1. Canonical Engine episode scope requires semantics equivalent to `(engine_instance_scope, episode_id)`; no concrete token algorithm is selected.
2. Canonical logical `match_id` must come from a validated game/platform source. The name `gameId` alone does not prove per-match uniqueness.
3. Viewer UUID, GEP session ID, native episode counter, seat index, seed, timestamp, rollout index and array position must not be substituted for canonical identity.
4. UnitInstance UUID must be interpreted within Engine/episode/ownership scope. Same-seed factory resets can repeat UUID values; implicit value copies preserve UUID.
5. Shop opportunity identity must not be inferred from champion ID, shop slot or physical UnitInstance UUID.
6. Missing identity remains incomplete/unavailable with a reason. No timestamp, latest-value, call-order or array-index fallback is allowed.

Temporary rollback/projection copies are non-owning values; they do not create a second active physical owner.

Still unproven: the complete implicit C++ copy/assignment/destruction graph, a no-duplicate-active-owner invariant, global/Engine-scoped collision policy, and a canonical decision sequence. ### 3.2 Correlation contract

A valid future PPO transition must bind observation, exact masks, selected action, log-probability, value, reward/validity, next-state reference and replay record to the same canonical Engine episode, player seat and typed decision identity. Mask bytes/order and action/mask contract versions must be independently verifiable.

Sequence namespaces remain distinct: Engine decision, observation snapshot, mask snapshot, Composition Intelligence player sequence, native strategic sequence, ContextBridge sequence, JSONL append, Viewer session sequence and PPO rollout timestep. Numeric equality does not imply identity.

A missing or mismatched identity must be represented as incomplete/stale/incompatible and rejected from canonical decision consumption. Do not substitute latest masks or join by rollout index, seat, timestamp or Viewer session.

### 3.3 Live Overwolf boundary

The intended live path remains GEP capture → sanitized live-state snapshot → validated native import → Engine-derived legal context/masks → PPO inference → read-only recommendation. The native simulation reset/step path is not a substitute for live-match observation. Acceptance requires a real sanitized GEP fixture and end-to-end recommendation replay that does not call Engine `reset()`/`step()`, execute actions, or treat simulation masks as live-match masks.

## 5. Workstream 4 — elimination item terminal policy

The current elimination path returns champion copies to UnitPool and clears board/bench UnitInstances but does not explicitly retire ItemEngine's UUID-keyed equipment map, loose components, completed inventory or pending queue. The retained equipment map is not shown as an active target and is not fully enumerated by the audit snapshot; this is an ownership/diagnostic ambiguity, not proof of cross-player leakage.

Three policies are documented:
- **A — retire/discard** all item ownership after capturing an immutable terminal snapshot;
- **B — return equipped items to the eliminated player's own bag, then freeze it**;
- **C — retain current internal state until Engine reset**.

Policy A is recommended provisionally because it gives the eliminated player no continuing active inventory and avoids orphaned active ownership. This recommendation is **not an accepted game rule or domain decision**.

Before choosing A, inspect ItemEngine metric consumers and placement/reward attribution. A generic reset must not erase counters needed for terminal reward/replay. The user/domain owner must explicitly select A, B or another policy. No implementation is authorized by this document.
