# Observation Schema v2 Identity Field Semantics Reconciliation v1

**Status:** documentary correction to the v2 proposal; not runtime-approved. PR #451 adds executable validation for this contract.  
**Target:** new-arquiteture.  
**Related:** Decision Identity Schema v2 Design; Engine Identity Scope Reconciliation; Native Engine Instance and Episode Identity Scope Audit; Viewer–Engine Session Correlation Audit; Observation Identity v1→v2 Crosswalk; Sequence Namespace Registry v2.  
**Tracking:** issue #346.

> This note resolves field semantics only. It does not change runtime producers, hash algorithm, tensor projection, masks, PPO, or the Gate 8 boundary.

## 1. Prior problem

Observation Schema v2 and Decision Identity Envelope v2 require distinct match_id and engine_match_id fields, while also defining session_match_id and episode_id as separate metadata. Existing source audits reveal that the current Viewer logging path uses overlapping field names:

- ViewerSession generates a UUID and writes it to the record's match_id.
- The same Viewer correlation envelope copies native numeric episode_id into engine_match_id.
- The native Engine has no Engine-instance token; episode_id is local to one TFTEngine::Impl lifetime.
- Independent Engine objects can share the same numeric episode_id.
- The Viewer UUID is not an authoritative game match identity, and native episode_id alone is not a globally unique Engine-episode identity.

Without an explicit semantic distinction, an adapter could copy legacy Viewer fields directly into v2 and incorrectly mark a session-only record as a complete canonical Engine decision.

## 2. Technical rationale

A canonical decision envelope needs three independent identity dimensions:

1. **Logical game match** — identifies the game match from an authoritative game/platform source, when such a source is available.
2. **Engine episode scope** — identifies one episode within one particular native Engine object lifetime.
3. **Recording/session** — identifies the Viewer session or recorder that observed the match.

They have different producers, reset boundaries, and uniqueness guarantees. They must not share one field or be inferred from one another.

The existing Engine episode counter is not sufficient for dimension 2 because it restarts for each newly constructed Engine object. The Viewer UUID is not sufficient for dimension 1 because it is generated by the Viewer and can exist independently of a validated game/platform match identity.

## 3. Canonical field meanings

| v2 field | Normative meaning | Current source evidence | Canonical eligibility |
|---|---|---|---|
| match_id | Authoritative logical game-match identity from a validated game/platform source | No authoritative producer proven in the audited main-repository path | Required; incomplete if unavailable |
| engine_match_id | Canonical Engine-episode scope distinguishing Engine object lifetime + episode | No Engine-instance token exists in audited paths; native episode_id is only Impl-local | Required; incomplete until a scoped producer exists |
| session_match_id | Viewer recording/session UUID | ViewerSession creates UUID via uuid.uuid4() | Correlation only; excluded from canonical decision hash |
| episode_id | Native numeric episode counter within one TFTEngine::Impl lifetime | Native reset/step results and pybind preserve it; Python wrapper drops it from training-facing reset/step outputs | Metadata only; excluded from canonical decision hash |
| player_id | Episode-local seat token encoded as player-0 through player-7 | Native lobby and Python wrapper use integer array indices 0–7 | Deterministic seat representation; not a persistent player UUID |

### 3.1 match_id

The v2 field means a logical game-match identity that is sourced from an authoritative game/platform producer and validated before use. It must not be populated with:
- ViewerSession.match_id;
- episode_id;
- an Engine seed;
- a timestamp, directory name, rollout index, player seat, or array position.

The current audited main repository does not prove an authoritative producer for this field. If no validated source is available, it remains null and the identity cannot be marked complete. A future Overwolf/GEP source may be considered only after its exact field, lifecycle, uniqueness and transport are independently audited; this note does not assume such a field exists.

### 3.2 engine_match_id

The v2 field means a canonical Engine episode scope, not the raw numeric episode_id. Its semantic uniqueness domain must distinguish:
- two independent Engine objects created with the same seed; and
- two episodes created by resets of one Engine object.

The minimum semantic composition is equivalent to:

(engine_instance_scope, episode_id)

This is not a wire-format decision. No UUID algorithm, token format, process ID, seed-derived value, or persistence mechanism is selected here. The authoritative native Engine lifecycle owner must define and produce the scope before this field can be marked complete.

### 3.3 session_match_id

The Viewer UUID belongs here. It remains useful for recording, navigation, event grouping and explicit Viewer-to-Engine correlation. It is not part of the canonical decision identity hash and cannot repair a missing match_id or engine_match_id.

The existing Viewer JSONL/metadata shape may retain legacy match_id for historical compatibility, but a v2 adapter must map the Viewer-owned value to session_match_id and preserve the original source label.

### 3.4 episode_id and player_id

Keep native episode_id as metadata so diagnostics can preserve the counter value, but never use it alone as a globally unique Engine match key.

Keep player_id as the episode-local seat token. Because the v2 JSON Schema represents it as a string, serialize native seat index N as the exact token player-N, where N is 0 through 7; do not use leading zeros or another inferred ID format. This is a deterministic encoding of an existing array position, not a persistent participant UUID. It must be interpreted together with engine_match_id; player-0 in one Engine episode is not the same participant identity as player-0 in another episode.

## 4. Hash and namespace consequences

The v2 decision identity hash continues to include:
- authoritative match_id;
- canonical scoped engine_match_id;
- episode-local player_id;
- round;
- typed decision_sequence namespace/value;
- typed snapshot_sequence namespace/value;
- identity_version.

It continues to exclude:
- session_match_id;
- raw episode_id;
- timestamps and recorder append counters;
- Viewer sequence_id;
- PPO rollout timestep or array index.

The three proposed canonical Engine namespaces (tft.engine.decision, tft.engine.observation-snapshot, tft.engine.action-mask-snapshot) must be scoped to the canonical engine_match_id and player seat. Their current status remains proposed_not_implemented; this reconciliation does not promote them.

## 5. Required source-to-schema mapping

| Source record | v2 destination | Allowed transformation |
|---|---|---|
| Validated game/platform match identity | identity.match_id | Copy exact validated value with source provenance |
| Future authoritative Engine episode identity | identity.engine_match_id | Copy exact producer value; must encode Engine instance + episode semantics |
| Native episode_id | identity.episode_id | Preserve as metadata; do not promote to engine_match_id |
| ViewerSession.match_id | identity.session_match_id | Copy as Viewer session correlation with explicit source label |
| Native player array index N (0–7) | identity.player_id | Serialize deterministically as player-N; retain episode-local semantics |
| Viewer sequence_id | Typed Viewer/session source reference only | Preserve Viewer namespace; never use as Engine decision/snapshot sequence |
| CI, ContextBridge, native strategic, JSONL append sequences | Their own typed source-reference fields | Preserve producer namespace and scope; never substitute for canonical Engine sequences |

If a required source is absent, the adapter must emit a non-complete identity with an explicit reason and null canonical decision hash. It must not fill fields by copying similarly named legacy fields.

## 7. Architecture reconstruction review

1. **Prior problem:** v2 identity field names were required but the current Viewer record used match_id for a Viewer UUID and engine_match_id for a local numeric episode counter.
2. **Technical justification:** these values have different owners and uniqueness scopes; direct copying would create false canonical identity and invalid cross-Engine joins.
3. **New responsibility:** this note owns the normative source meaning and mapping rule for the v2 match, Engine, session, episode and player fields.
4. **Contract and invariants:** match_id is authoritative game-match identity; engine_match_id is Engine-instance + episode scope; Viewer UUID maps only to session_match_id; episode counter remains local metadata; player_id is player-N seat token scoped by engine_match_id.
5. **Cross-component impacts:** Observation Schema v2, identity hash, sequence registry, Viewer JSONL, native Engine lifecycle, Overwolf/GEP source audit, pybind, Python wrapper, PPO rollout and replay.
6. **Objective validation:** the schema and crosswalk descriptions agree; current producers are classified as missing/metadata/session-only where appropriate; no source field is promoted without proof; no runtime or tensor behavior changes.

### 5.1 Live-state envelope identifiers are separate source metadata

The approved Overwolf boundary document describes a canonical live-state envelope containing gameId, sessionId, revision and capturedAt. Their names alone do not prove that they can populate the v2 canonical identity fields:

| Live-state field | Safe interpretation from the current main-repository contract | v2 treatment |
|---|---|---|
| gameId | Game/product identifier; per-match uniqueness semantics are not established by this document | Do not map to match_id until the producer contract proves it identifies one logical match |
| sessionId | Overwolf capture/transport session identifier | Preserve as source-session metadata; do not alias it to Viewer session_match_id without an explicit correlation contract |
| revision | Source-state revision within its declared capture/session scope | Preserve as a typed GEP/live-state source reference; not an Engine decision or observation-snapshot sequence |
| capturedAt | Capture timestamp | Audit metadata only; not a sequence and not part of the decision identity hash |
| local-player index | Source-local player position/index | Map to player-N only after the source contract proves the same 0–7 seat semantics and scope |

The native import boundary must preserve these source identifiers independently from ViewerSession identity and native Engine episode metadata. A future source-to-Engine correlation record may relate them, but must retain both original typed references and must not rewrite a game/product ID or capture revision as an Engine identity.

gameId may become a valid match_id only if the authoritative GEP/live-state producer proves per-match uniqueness, lifecycle across reconnects, reset behavior and transport preservation. Until then, match_id remains unavailable for canonical v2 identity.


## 8. GEP match-id source path: implementation proof versus real-source proof — 2026-11-15

The Overwolf repository source pass now establishes the mapper's exact intended field path:

- `src/browser/services/gep/tft-live-state.mapper.ts` reads `info.match_info.match_info.match_id`.
- A textual value is retained; a numeric value is converted to its decimal string.
- `scripts/test-tft-snapshot-manager.js` supplies the synthetic nested value `778899` and asserts the canonical state receives `"778899"`.

This closes the earlier **unknown mapper path** question. It does not close the **authoritative producer** question: the fixture is authored test data, not a sanitized real GEP capture.

The lifecycle source also distinguishes:
- `TftSnapshotManager.sessionId`: random UUID created at manager construction and regenerated only by its explicit `reset(gameId)` method;
- `revision`: manager-local counter, reset to zero by `reset()`, incremented when canonical source state changes;
- `capturedAt`: refreshed on revision changes;
- `state.matchId`: mapped from the nested match-info leaf;
- recorder behavior: a changed known match ID causes a new full snapshot baseline, but the recorder does not itself reset the manager's session ID or revision.

The source audit has not yet proven that the actual Overwolf event/controller lifecycle invokes manager reset on every new match, reconnect, or game re-entry. Nor has it proven per-match uniqueness of the leaf across real matches. Therefore this evidence does **not** promote `identity.match_id` to canonical v2 availability.



## Native sequence mapping correction

The native `TFTEngine::Impl::decision_sequence` is a per-Engine snapshot-publication counter, not a per-player decision counter. It increments once for each `ResetResult`/`StepResult`, is shared by all eight player rows, and remains monotonic across episode resets. Decision Identity v2 maps it to `snapshot_sequence` under `tft.engine.observation-snapshot`. The per-player `decision_sequence` remains null until an authoritative producer exists.

Consequently, current native snapshots remain `partial` identity until authoritative logical `match_id` and per-player decision sequence are supplied. A partial identity cannot carry valid mask, Critic, anti-loop, or strategic-owner context merely because local integer counters happen to match.


## PR 1 correction — complete native identity without an external match ID

The source now provides engine_instance_id, episode_id, and per-player player_decision_sequences through native results and wrapper snapshot metadata. The earlier “no Engine-instance token / no per-player sequence” conclusions are superseded.

match_id remains an optional external logical match identifier. When no authoritative platform producer exists, it stays null. A native decision may still have complete identity when the canonical Engine-episode scope, player seat, round, per-player decision sequence and Engine snapshot sequence are all valid. The explicit null match_id is included in the RFC 8785 decision hash; it is never synthesized from Viewer session identity or episode counters.

The canonical physical unit identity is (engine_match_id, uuid). player_id is ownership metadata, not part of the physical identity, so moving an instance between ownership domains does not create a new physical unit identity.
